# PointPlux Hotel & Suites — Website

A complete, static, multi-page website for PointPlux Hotel & Suites, built from the
brochure PDF, styled in the spirit of the Bracken Court Hotel reference site.

## What's inside

```
site/
├── index.html                 Homepage
├── rooms.html                 Rooms & Suites
├── facilities.html            Exotic Bar, Workman's Lounge, Lounge, Exclusive Hall
├── location.html              Location & landmarks
├── contact.html                Contact page + enquiry form
├── thank-you.html              Shown after a successful form submission
├── privacy-policy.html
├── terms-and-conditions.html
├── 404.html                    Custom error page
├── robots.txt
├── sitemap.xml
├── site.webmanifest
├── css/style.css               All styling
├── js/main.js                  Nav, hero slider, cookie banner, form validation, loading states
├── js/ga.js                    Google Analytics (GA4) — placeholder ID, see below
└── images/
    ├── optimized/               Compressed JPG + WebP versions of every brochure photo
    └── icons/                   Favicon set, app icons, and the Open Graph share image
```

## WhatsApp integration

All primary calls-to-action — the **Book Now** button (nav + hero), the **sticky mobile
CTA**, and the **contact form** — go straight to WhatsApp at **+234 703 009 1259**,
using [wa.me](https://wa.me) links with a pre-filled message. No backend, server, or
paid service is required for this to work.

- **Book Now / Enquire buttons** open WhatsApp with a short pre-written message.
- **Contact form**: when the visitor submits, the site validates the fields, builds a
  message from their Name / Email / Phone / Interest / Message, opens WhatsApp in a new
  tab with that message pre-filled and ready to send, and then shows the on-site
  "Almost There!" confirmation page (`thank-you.html`).
- To change the WhatsApp number later, update `WHATSAPP_NUMBER` in **two places**:
  `build_site.js` (top of the file) and `site/js/main.js` (inside the form submit handler).
  Then run `node run_build.js` to regenerate the HTML.
- Note: WhatsApp only opens automatically if the visitor has WhatsApp installed
  (mobile) or WhatsApp Web linked (desktop) — this is a limitation of `wa.me` links
  generally, not something specific to this site.

## Before you go live

1. **Domain** — the code currently uses `https://www.pointpluxhotel.com` as a placeholder
   in `sitemap.xml`, `robots.txt`, and the Open Graph/canonical tags in every page's
   `<head>`. Once you register a real domain, find-and-replace that URL everywhere.
2. **Google Analytics** — open `js/ga.js` and replace `G-XXXXXXXXXX` with your real GA4
   Measurement ID (see: analytics.google.com → Admin → Data Streams → your web stream).
3. **Contact form** — the form currently *simulates* a submission (it just redirects to
   `thank-you.html` after ~1 second) so it works with zero backend. To actually receive
   enquiries by email, the easiest free option is
   [Formspree](https://formspree.io): create a free form, then in `js/main.js` replace the
   `setTimeout(...)` block inside the submit handler with a real `fetch()` POST to your
   Formspree endpoint.
4. **Google Map** — the embedded map in `location.html` and `contact.html` uses a generic
   search query for "Joju Road, Sango Otta." For a pinpoint-accurate marker, get your
   exact coordinates from Google Maps and swap the `src` URL on the `<iframe class="map-embed">`.
5. **Social links** — the footer's Facebook/Instagram/WhatsApp icons currently link to `#`.
   Update the `href` values in every page's footer (or edit `build_site.js`'s `footer()`
   function once and re-run the build — see below).

## Editing content

Every page is generated from a small JS file in `pages/` (e.g. `pages/index.js`) which
plugs into the shared header/footer template in `build_site.js`. To change shared elements
like the navigation, footer, or cookie banner, edit `build_site.js` once; to change a
single page's content, edit that page's file in `pages/`.

After editing, regenerate all HTML files:

```bash
node run_build.js
```

This rewrites every `.html` file in `site/` and regenerates `sitemap.xml`.

If you'd rather not touch the build scripts, you can also edit the `.html` files
directly inside `site/` — just note that a future `node run_build.js` run will
overwrite direct HTML edits, since they're regenerated from `pages/*.js`.

## Deploying — GitHub Pages (free)

```bash
cd site
git init
git add .
git commit -m "Initial PointPlux Hotel & Suites website"
git branch -M main
git remote add origin https://github.com/<your-username>/pointplux-hotel.git
git push -u origin main
```

Then in the repo on GitHub: **Settings → Pages → Source: `main` branch, `/ (root)`** — Save.
Your site will be live at `https://<your-username>.github.io/pointplux-hotel/` within a
few minutes. To use a custom domain, add a `CNAME` file in `site/` with your domain name
and point your domain's DNS to GitHub Pages per GitHub's custom-domain docs.

## Deploying — Netlify (also free)

Drag the `site/` folder onto [app.netlify.com/drop](https://app.netlify.com/drop), or
connect your GitHub repo in the Netlify dashboard for automatic redeploys on every push.

## Local preview

From inside `site/`, run any static file server, e.g.:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000` in your browser.

## Getting the PointPlux logo to show in Google Search (instead of the globe icon)

The site is already technically set up for this — every page links to a full icon set
(16x16 up to 512x512, including the 48x48 and 96x96 sizes Google specifically looks for)
built from your actual logo, and `robots.txt` doesn't block the `images/` folder, so
Googlebot can reach every icon file.

That said, **this isn't something code alone can guarantee** — Google only shows a
site's own icon in search results once it has:

1. **Crawled and indexed the live site.** Right now these files only exist in this
   project folder — Google can't see anything until the site is deployed to a real,
   public domain (GitHub Pages, Netlify, or your own hosting).
2. **Re-crawled it enough times to pick up the icon**, which is a fully automatic
   process on Google's own schedule — typically anywhere from a few days to a few
   weeks after the domain goes live, even with everything set up correctly.

**Once the site is live, speed this up with:**

- Sign up for free at [Google Search Console](https://search.google.com/search-console),
  add your domain, and verify ownership.
- Submit `sitemap.xml` there (Search Console → Sitemaps).
- Use "Request Indexing" on the homepage URL to nudge Google to crawl it sooner.
- Make sure the favicon file itself stays reachable at a stable URL after launch —
  don't rename or move the `images/icons/` folder.

Until the domain is live and indexed, search engines (and browser tab previews of a
`file://` or `localhost` preview) will keep showing a generic globe/placeholder icon —
that's expected, not a bug in the site.
